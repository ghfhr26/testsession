# explain-code: 한국어 설명 주석 달기

대상 파일: $ARGUMENTS

코딩 초보자가 코드를 읽고 이해할 수 있도록, 원본 파일에 한국어 설명 주석을 추가한다.

## 1. 시작 전 확인

1. **경로가 없으면** 어떤 파일에 주석을 달지 질문한다. 폴더가 주어지면 어떤 파일을 할지 질문한다.
2. **주석 대상은 프로젝트 안의 `.ts`, `.tsx`, `.js`, `.jsx`, `.css` 파일 5종류뿐이다.** 이 확장자면 `next.config.ts`, `next-env.d.ts` 같은 설정용 파일도 포함한다. `/explain-code` 실행 자체를 수정 허락으로 본다.
   - `next-env.d.ts`는 `next dev` 실행 때 Next.js가 다시 만들 수 있어서 주석이 사라질 수 있다. 이 파일에 주석을 달 때는 이 점을 사용자에게 알린다.
3. **아래 파일은 주석을 달지 않는다.** 파일을 수정하지 않고, 이유를 말한 뒤 대화창에서만 설명한다.
   - 위 5개 확장자가 아닌 모든 파일 (예: `.json`, `.mjs`, `.md`, `.svg` 등. `eslint.config.mjs`, `tsconfig.json`, `package.json`도 여기에 해당)
   - `node_modules` 안의 파일 (확장자가 5개 중 하나여도 제외)
   - 프로젝트 폴더(huddlingclub) 밖의 파일 (확장자와 관계없이 대화창 설명도 하지 않고 거절한다)
4. **실행 방식에 따라 수정 여부를 정한다.**
   - 사용자가 `/explain-code`를 직접 입력했으면 바로 주석을 추가한다.
   - 사용자가 명령어 없이 "이 코드 설명해줘"처럼 요청해서 Claude가 스스로 이 스킬을 쓰는 경우에는, **파일을 수정하기 전에 "원본 파일에 주석을 추가할까요?"라고 먼저 물어본다.** 거절하면 대화창에서만 설명한다.

## 2. 주석 다는 규칙

- **코드 동작은 절대 바꾸지 않는다.** 주석 추가만 한다. 코드의 순서, 이름, 공백, 줄바꿈, 포맷도 건드리지 않는다.
- **기존 주석은 그대로 둔다.** 영어 주석이든 이전에 단 한국어 주석이든 지우거나 고치지 않는다. 설명이 없는 곳에만 추가한다.
- **덩어리 단위로 단다.** 한 줄마다 달지 않는다. 아래 위치 위에 주석을 단다.
  - 파일 맨 위: 이 파일이 무엇을 하는 파일인지 1~3줄
  - 함수, 컴포넌트, 타입 정의 위
  - 이해하기 어려운 중요한 블록(조건문, 반복문, 데이터 처리, 폼 처리 등) 위
- **"무엇을" + "왜"를 쓴다.** 코드를 그대로 읽어주는 주석(예: `// i를 1 증가시킨다`)은 쓰지 않는다.
- **쉬운 한국어로 쓴다.** 전문 용어(예: Server Action, Suspense, props)는 처음 나올 때 괄호로 짧게 풀어 쓴다.
- 파일 형식에 맞는 주석 문법을 쓴다.
  - TS/JS: 함수·컴포넌트 위에는 `/** ... */`, 블록 위에는 `//`
  - JSX(화면 마크업) 안: `{/* ... */}`
  - CSS: `/* ... */`

## 3. 정확성

- **모르는 것을 아는 척하지 않는다.** 확실하지 않은 내용을 추측으로 주석에 쓰지 않는다. 확인이 필요하면 사용자에게 질문한다.
- Next.js 관련 코드는 이 프로젝트의 Next.js 16이 학습 데이터와 다르므로, 설명하기 전에 `node_modules/next/dist/docs/`의 관련 문서를 확인한다.
- 다른 파일에서 가져온 함수나 컴포넌트는 그 파일을 읽고 나서 설명한다.

## 4. 마친 뒤

1. 주석 외에 코드가 바뀐 곳이 없는지 확인한다.
2. `npm run lint`를 실행해 에러가 없는지 확인한다. 에러가 나거나 실행하지 못했으면 숨기지 말고 그대로 알린다.
3. 사용자에게 짧게 보고한다.
   - 주석을 단 위치(함수·블록 이름)
   - 이 파일의 핵심 흐름 한두 줄 요약
   - 주석을 달면서 확인이 필요했던 점이나 질문
